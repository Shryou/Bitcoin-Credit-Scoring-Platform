## 1. 專案定位

### 1.1 問題
- 全球約 14 億成年人沒有銀行帳戶，但在菲律賓、肯亞、薩爾瓦多、奈及利亞等地，越來越多人用比特幣／閃電網路收付款。
- 傳統信用評分依賴銀行與信用卡紀錄，這群人沒有這些紀錄，等於「信用隱形」。
- 現有 DeFi 借貸（如 Aave、Compound）多半要求 **超額抵押（>100%）**。這群人本來就缺資金，結果還是借不到錢。

### 1.2 解法
把使用者的**鏈上／閃電網路交易行為**和**替代資料**交給 AI 計算信用分數，再讓 DeFi 借貸池依分數提供差異化條件：
**分數越高 → 抵押率越低、利率越低、額度越高。**
同時用零知識證明（ZK）的概念，讓使用者「證明自己的分數達到門檻」，但不必公開交易明細。

### 1.3 刻意不做（Non-goals）
- 真實錢包連線、私鑰、真實上鏈交易
- 真實的機器學習訓練（權重是預先設定、具合理性的示範值）
- 帳號登入、後端伺服器
- 真實即時幣價（使用固定的**模擬匯率**，畫面上會標示）

## 3. AI 信用評分模型

### 3.1 特徵（全部正規化到 0–1）

| # | 特徵 | 計算方式（從模擬交易算出） | 權重方向 |
|---|---|---|---|
| F1 | 帳戶年齡 | 月數 ÷ 24，上限 1 | ＋ |
| F2 | 交易頻率 | 每月平均筆數 ÷ 300，上限 1 | ＋ |
| F3 | 收入穩定度 | 1 − 月收入變異係數（CV），下限 0 | ＋＋ |
| F4 | 交易對手多樣性 | 對手分布的 Shannon entropy ÷ 最大值 | ＋ |
| F5 | 儲蓄率（HODL） | (流入 − 流出) ÷ 流入 | ＋ |
| F6 | 還款紀錄 | 準時還款比例；**沒有紀錄給 0.5（中性）** | ＋＋＋ |
| F7 | 社群擔保 | 擔保人數 ÷ 5，上限 1（擔保人本身也要有分數） | ＋ |
| F8 | 替代資料 | 手機話費／水電以 sats 準時繳納的比例 | ＋ |
| F9 | 風險訊號 | 和高風險地址互動、異常大額流出（0 = 無） | － － |

### 3.2 計算公式（業界標準計分卡）

```
z        = β0 + Σ βi · xi                 （邏輯迴歸）
P(良好)   = 1 / (1 + e^(−z))
odds     = P / (1 − P)
Score    = Offset + Factor · ln(odds)
Factor   = PDO / ln 2      （PDO = 40：odds 每翻倍加 40 分）
Offset   = 校準到「odds 20:1 ≈ 620 分」
分數範圍  夾在 300–850
```

**每個特徵的貢獻分數** = `Factor × βi × (xi − 平均值i)`。
所有貢獻加總剛好等於「總分 − 基準分」，所以可以畫成 **SHAP 風格的瀑布圖**，完整呈現每個因子「加了幾分、扣了幾分」。

### 3.3 信用等級與借款條件

| 等級 | 分數 | 抵押率 | 年利率 APR | 額度上限 |
|---|---|---|---|---|
| A | 750+ | 50% | 6% | 5,000,000 sats |
| B | 680–749 | 80% | 9% | 2,000,000 sats |
| C | 600–679 | 110% | 13% | 800,000 sats |
| D | 520–599 | 150% | 18% | 300,000 sats（信用建立貸款） |
| E | < 520 | 200% | — | 僅能純抵押借款 |

> 註：本規格書內的「聰」與 sats 同義；介面上一律顯示「聰」。
>
> 抵押率低於 100% 的部分（A、B 級）由**保險準備金**承擔違約風險，這個機制會在出借人儀表板呈現。

### 3.4 公平性設計（模型內部規則，不在介面上另寫說明頁）
- **不使用**性別、族群、國籍、宗教等受保護屬性
- 「沒有紀錄」視為中性，不懲罰新用戶
- 可解釋：每個分數都附上原因說明，以及「如何提升分數」的建議

## 4. 頁面結構與功能

單頁應用程式，上方分頁列有四個分頁：**信用評分｜借貸池｜出借人｜隱私證明**。打開後直接進入「信用評分」。右上角顯示目前角色、錢包（模擬）、主題切換、重置按鈕。

### 4.1 借款人：AI 信用評分
1. **連接錢包（模擬）**：選角色 → 連線動畫 → 顯示錢包地址（假資料）
2. **交易分析**：月收支長條圖（SVG）、最近交易列表、統計摘要
3. **AI 分析動畫**：逐一顯示 F1–F9 的萃取過程（有真實數值，不是假裝跑）
4. **結果**：
   - 儀表盤顯示分數和等級
   - 特徵雷達圖
   - **SHAP 瀑布圖**（每個特徵的加減分）
   - 白話解釋，例如「你的收入穩定度高於 82% 的用戶」
   - 改善建議，例如「再準時還款 2 次，可升到 B 級」
5. **自訂模式**：9 個滑桿，拖動時分數、瀑布圖、等級即時變化

### 4.2 DeFi 借貸池
- 依目前分數顯示可借的條件（抵押率、APR、額度）
- 借款模擬器：輸入金額 → 自動算出需要的抵押、每月還款額、違約損失試算
- 「確認借款」→ **智能合約自動審核清單**，逐條動畫打勾：
  1. 零知識證明驗證：信用分數 ≥ 該等級門檻
  2. 借款金額 ≤ 等級額度上限
  3. 抵押品 ≥ 所需抵押率
  4. 風險訊號檢查（F9）：無高風險地址互動
  5. 資金池可用流動性充足
  - 全部通過 → 顯示「核准」與放款耗時 → 產生貸款
  - 任一條失敗 → 該條顯示紅色 ❌ 和具體原因（例如「抵押品不足，還差 45,000 聰」），不放款
- **時間快轉**：「快轉 1 個月」，可選擇 ✅ 準時還款／⚠️ 逾期／❌ 違約
- 每個月的結果都會回饋到 F6，**分數歷史折線圖**即時更新
- 違約時展示清算流程：抵押品被拍賣，保險準備金補足缺口

### 4.3 出借人儀表板
- 存入／提領 sats（模擬）
- 資金池總覽：總存款、總借出、**使用率**、準備金
- **利率模型曲線**：採用 Aave 式的 kink 模型，使用率越高利率越高，並標出目前所在的點
- 依信用等級的資金配置甜甜圈圖
- 各等級違約率、預期收益、風險調整後收益
- 和 4.2 共用狀態：借款人借錢後，池子使用率和 APY 會跟著變

### 4.4 ZK 隱私證明
- 情境：「出借方只需要知道你的分數 ≥ 650，不需要看到你的交易」
- 三步驟動畫：**Commit**（承諾分數）→ **Prove**（產生證明）→ **Verify**（驗證通過）
- 對照圖：左邊「傳統方式：交出全部交易明細」，右邊「ZK：只給一個 ✅」
- 可以調整門檻，看分數不夠時驗證失敗
- 畫面會標註：「概念示範，雜湊由前端模擬，並非真實 zk-SNARK」

### 模型參數

- 計分卡：PDO = 40，Offset = 620 − (40 / ln2) × ln20 ≈ 447.1，β₀ = −1.38
- 權重 β：F1 1.00、F2 0.96、F3 1.00、F4 0.80、F5 2.40、F6 2.40、F7 0.64、F8 0.80、F9 −2.40
- 平台平均（瀑布圖基準）：F1 0.40、F2 0.40、F3 0.55、F4 0.50、F5 0.12、F6 0.55、F7 0.25、F8 0.65、F9 0.05 → 基準分數約 593

### 借貸池參數

- 初始資金池：存款 5,000 萬聰；其他借款人借出 A 1,200 萬、B 1,000 萬、C 800 萬、D 300 萬（使用率 66%）；保險準備金 250 萬聰
- 利率模型：基準利率在使用率 80% 以下時線性升到 8%，超過 80% 後斜率提高，100% 時達 48%；與 66% 基準點的差額作為「市場調整」，加在各等級利率上
- 利息分配：90% 給出借人、10% 提撥保險準備金
- 逾期：加收當期還款額 5% 的罰金，計入準備金
- 違約：沒收抵押品並以 95% 拍賣回收，缺口先由準備金補足，不足時才由出借人分攤；拍賣剩餘退回借款人
- 各等級年違約率：A 1%、B 2.5%、C 5%、D 9%；違約損失率 = max(5%, 1 − 抵押率 × 95%)
- 時間快轉時，非目前角色的貸款一律視為準時還款，所有已連接角色每月有淨收入入帳
